# Stage 07 — i18n scaffolding and Arabic type

**Est** 1.5 days · **Branch** `stage/07-i18n` · **Depends on** 03
**Gate** 100% of strings externalised, zero inline `t('en','ar')` pairs left, RTL screenshots pass, translator CSV generated.
**Moves** Bilingual 5.0 → 7.5 (9 when the translation lands)

## Objective

Two things: make Arabic *look* like the designed product, and turn the remaining
translation work into a CSV someone can fill in without touching code.

## The defects

**1. No Arabic typeface is loaded.** `globals.css` requests DM Sans and Manrope.
Neither carries Arabic glyphs. So every Arabic string falls back to whatever the
system provides — Geeza Pro, Segoe UI, Noto Naskh — at metrics the layout was never
tuned for. The whole AR experience silently loses the typography, in a market where
Arabic is half the point.

**2. Strings are inline, everywhere.** Hundreds of `t('English', 'عربي')` pairs are
embedded in the feature components. `KinesioApp.tsx` alone has dozens.
`ProgrammeScreen` builds sentences by interpolating into both branches. A translator
cannot work on this, and neither can a third language.

**3. `dir` is on a `<div>`, not `<html>`.** `KinesioApp` sets
`<div className="app-shell" dir={arabic ? 'rtl' : 'ltr'}>` while the effect only sets
`document.documentElement.lang`. Scrollbar side, native form control mirroring, and
`::selection` behaviour all key off the document direction.

**4. Clinical Arabic is interim, by design.** `DECISIONS.md` is explicit: the 136
exercise names and presentation-specific prose "need a qualified clinical Arabic
translation pass", and the generic type labels are placeholders. `SessionPlayer`
proves it — the Arabic branch for cues serves three generic sentences from an array
regardless of which exercise is showing:

```tsx
{arabic ? ['ابدأ من وضع مريح.', 'تحرّك ببطء…', 'واصل التنفس…'][i] : c}
```

That is honest interim behaviour and must not be shipped as if it were a translation.

## Tasks

### 1. Load an Arabic face

`IBM Plex Sans Arabic` (pairs with a grotesk cleanly, has real weights) or
`Noto Kufi Arabic`. Via `next/font/google` alongside the stage-02 work:

```ts
const arabic = IBM_Plex_Sans_Arabic({ subsets:['arabic'], weight:['400','500','600'], variable:'--font-ar', display:'swap' });
```

```css
:root{ --font-sans: var(--font-dm), sans-serif }
:root:lang(ar){ --font-sans: var(--font-ar), sans-serif }
:lang(ar) h1, :lang(ar) h2, :lang(ar) h3{ font-family: var(--font-ar), sans-serif }
```

Arabic runs longer than English and sits differently on the baseline. Check the
places where the current design is tight: `.brand`, `.nav-item` labels at
`--fs-label`, `.badge`, `.phase-status`, `.dose-box`. Adjust `line-height` for
`:lang(ar)` rather than shrinking the type — the 11px floor from stage 03 holds here
too.

### 2. Move `dir` to the document

```ts
useEffect(() => {
  document.documentElement.lang = arabic ? 'ar' : 'en';
  document.documentElement.dir  = arabic ? 'rtl' : 'ltr';
  localStorage.setItem('kinesio-language', arabic ? 'ar' : 'en');
}, [arabic]);
```

Then remove the `dir` prop from `.app-shell`. **Keep** the explicit `dir="ltr"`
wrappers around the 3D viewers and `BodySprite` — `DECISIONS.md` states Arabic
mirrors the chrome, not the anatomy, and that is correct: a mirrored body would
misreport which side hurts.

### 3. Externalise every string

```
messages/en.json
messages/ar.json
```

Keyed by screen and purpose: `session.cue.breathe`, `home.heading`,
`programme.notice.highIrritability`. Flat two-level keys, no deep nesting.

Replace `t(en, ar)` with `t('key')` reading from the active bundle, keeping the same
function signature shape so the change is mechanical per file. Interpolation becomes
named params — `t('home.dose', { minutes, character, region })` — because Arabic word
order differs and cannot be built by concatenation. The current
`ProgrammeScreen`/`HomeScreen` pattern of interpolating into an English template
string and hand-writing a different Arabic sentence is exactly what this fixes.

Add an ESLint rule (or a `scripts/check-i18n.mjs` in CI) banning:

- string literals containing Arabic characters anywhere in `src/**/*.tsx`
- any `t()` call with two arguments where the second is a string literal

That is what keeps the bundles from rotting.

**Clinical content stays in `src/data/*.json`** — `nameAr` on exercises, Arabic
region labels in `regions.json`. Those are clinical data, not UI copy (rule 4 in
`CLAUDE.md`). The extractor reads them but does not move them.

### 4. Logical properties audit

Stage 03's stylesheets should already be clean, but sweep for `left`, `right`,
`margin-left`, `padding-right`, `text-align: left|right`, and `border-left|right`.
Replace with `inline-start`/`inline-end` equivalents. Known offenders in the current
file: `.canvas-tools{right:14px}`, `.article-card > svg{right:24px}`,
`.home-session > .home-body{right:-20px}`, `.learning-art{right:-35px}`,
`.exercise-demo{padding:0 50px 0 0}`.

Also: the swipe direction in `SessionPlayer` already flips with `arabic` — keep that,
and add a test for it.

### 5. RTL screenshot tests

Extend `tests/e2e/responsive.spec.ts` (from stage 03) with an Arabic pass: same
widths, `dir=rtl`, all ten screens. Assert no horizontal overflow and no clipped
text. This is where Arabic's longer strings will break things.

### 6. Generate the translator packet

`scripts/i18n-export.mjs` emits `docs/handoff/translation.csv`:

| key | english | current_arabic | status | context | max_chars |
|---|---|---|---|---|---|

Where `status` is one of:

- `missing` — no Arabic at all
- `interim` — a generic placeholder standing in for specific content (the
  `SessionPlayer` cue array, the generic exercise-type labels, the single Arabic
  sentence covering several English clinical notices)
- `ok` — a real translation that still wants review

Include the 136 exercise `name`/`nameAr` pairs and the presentation education prose
from `presentations.json`, flagged `interim`, with `context` naming the screen and
whether the string is safety-critical. `max_chars` comes from measuring the English
in the layout — a translator needs to know that `.phase-status` has room for about
18 characters.

Ship it with `docs/handoff/TRANSLATOR-BRIEF.md`.

## Gate

```bash
node scripts/check-i18n.mjs      # 0 inline Arabic literals, 0 two-arg t() calls
node scripts/i18n-export.mjs     # writes the CSV, prints counts by status
npm run test:e2e                 # includes the RTL pass
```

- [ ] Arabic webfont loads and is applied under `:lang(ar)`
- [ ] `dir` on `<html>`; viewers still explicitly `ltr`
- [ ] Every UI string in `messages/*.json`; check script green
- [ ] Interpolation uses named params, not concatenation
- [ ] No physical direction properties left in the stylesheets

- [ ] `translation.csv` generated with status counts reported in the PR
- [ ] `DECISIONS.md` updated: what is now real vs. still interim

## The remaining 1.5 points

This stage does not translate anything. It makes translating a one-pass job: hand
`translation.csv` and the brief to a medical Arabic translator, paste the returned
column into `ar.json`, flip the `interim` flags, re-run the RTL screenshots. That is
the 9.

Until then, keep the interim labels visibly generic rather than confidently wrong. A
generic Arabic exercise-type label is honest; a machine-translated clinical cue that
reads fluently and means something slightly different is not.
